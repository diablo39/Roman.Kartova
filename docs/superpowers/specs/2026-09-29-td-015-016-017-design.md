# TD-015 / TD-016 / TD-017 — System-route arch sweep, SPA runtime config, re-auth loop breaker — Design

**Items:** TD-015, TD-016, TD-017 (`docs/engineering/tech-debt.md`)
**ADRs:** [ADR-0118](../../architecture/decisions/ADR-0118-platform-admin-isolation.md) (admin isolation, own origin + CSP), [ADR-0060](../../architecture/decisions/ADR-0060-three-probe-health-checks-aspnet-core-framework.md) (health contract — unchanged), [ADR-0116](../../architecture/decisions/ADR-0116-spa-holds-tokens-bff-deferred.md) (SPA-held tokens, CSP), [ADR-0082](../../architecture/decisions/ADR-0082-modular-monolith-architecture.md) (NetArchTest), [ADR-0084](../../architecture/decisions/ADR-0084-playwright-mcp-for-frontend-development.md) (browser verification)
**Date:** 2026-09-29
**Status:** approved (brainstorming 2026-09-29)

## Context

Three open tech-debt items from E-01b.F-03 (S-01, S-02):

- **TD-015** — `/health/detailed` requires `PlatformAdminOnly` but is mapped in `Program.cs`; the `EndpointRouteRules` sweep maps only `IModuleEndpoints` types, so the admin-policy rules never see it. Its binding is pinned by one integration test plus a comment.
- **TD-016** — OIDC authority / client id and API base URL are inlined at `vite build` (`VITE_*` Dockerfile `ARG`s), so `web` and `web-admin` need one image per environment. Worse for `web-admin`, which is always cross-origin to the API (ADR-0118).
- **TD-017** — a 401 calls `signinRedirect()`; if SSO returns and the API still answers 401 (stale/rejected token, clock skew, misconfigured realm) the SPA redirects again, forever. Both SPAs share the path via `web/src/shared/oidc/useApiAuthBridge.ts`.

## Scope

In:
- TD-015: move system routes into an `IModuleEndpoints` class; extend the arch sweep; ops-admin allowlist rule; source guard on `Program.cs`.
- TD-016: runtime `/config.js` rendered by nginx envsubst for both SPAs; Dockerfile/compose/Helm/CI/docs switched from build args to env vars.
- TD-017: timed `sessionStorage` re-auth marker + full-app "session rejected" panel in both SPAs.

Out (YAGNI):
- Deriving `CSP_EXTRA_ORIGINS` from the new config vars — stays a separate env var.
- Escaping/validating operator-supplied config values — trusted deploy input; documented constraint (no `'` or `"`).
- Driving the arch sweep off the real `Program` host (rejected — pulls full DI/config into the arch tier).
- Async `/config.json` bootstrap (rejected — needs an async boot path and lazy module-level config).

## Decisions (confirmed in brainstorming)

| # | Decision | Rejected alternative |
|---|---|---|
| D1 | TD-016 via synchronous `/config.js` (`window.__KARTOVA_CONFIG__`) loaded by `<script src>` before the bundle | Async `/config.json` fetch before mount |
| D2 | Resolution order per key: runtime (non-empty) → `VITE_*` → current localhost default | Fail hard when runtime config missing |
| D3 | Same config keys for both apps; each image serves one app (`APP=web|admin`) | Per-app key names |
| D4 | TD-015 via `SystemEndpoints : IModuleEndpoints` in `Kartova.Api` + explicit ops-admin allowlist + `Program.cs` source guard | Sweep the real `Program` host via `WebApplicationFactory` |
| D5 | TD-017 via timed marker (30 s window), cleared by any authenticated non-401 response; panel rendered by the auth bridge in place of the app | Untimed one-shot marker |
| D6 | Pending `docker-compose.yml` KeyCloak heap cap committed on this branch as its own `chore(compose)` commit | Separate branch |

## Components

### TD-015 — System endpoints in the arch sweep

**`src/Kartova.Api/SystemEndpoints.cs`** (new) — `internal sealed class SystemEndpoints : IModuleEndpoints`, parameterless ctor. Owns everything currently mapped directly in `Program.cs`:

| Name | Verb | Template | Auth |
|---|---|---|---|
| `HealthLive` | GET | `/health/live` | as today |
| `HealthReady` | GET | `/health/ready` | as today |
| `HealthStartup` | GET | `/health/startup` | as today |
| `HealthDetailed` | GET | `/health/detailed` | `PlatformAdminAuth.Policy` |
| `GetOpenApiDocument` | GET | `/openapi/{documentName}.json` | `AllowAnonymous` |
| `GetVersion` | GET | `/api/v1/version` | `AllowAnonymous` |

`GetVersion` moves with it (still `Assembly` of `Kartova.Api`). Health-check options/writers unchanged. URLs and runtime behaviour unchanged (ADR-0060).

**`src/Kartova.Api/Program.cs`** — the direct `Map*` block is replaced by adding `new SystemEndpoints()` to `endpointModules` alongside `OrganizationAdminModule`. The "mapped outside MapAdminModule…" comment is deleted.

**`tests/Kartova.ArchitectureTests/EndpointRouteRules.cs`**:
- `BuildArchTestApp()` registers `AddHealthChecks()` and `AddOpenApi()` so the new mappings build (no real checks needed).
- `ExpectedEndpoints` gains the six rows above.
- `OpsAdminRoutes = ["/health/detailed"]` — the only non-`/api/v1/admin/` routes allowed to carry `PlatformAdminOnly`. `PlatformAdminOnly_is_used_only_under_the_admin_prefix` exempts exactly this set.
- New `Every_ops_admin_route_requires_PlatformAdminOnly` — each allowlisted route exists (anti-vacuity), carries the policy, and is not `AllowAnonymous`.
- New `Program_maps_no_routes_directly` — locates the repo root (walk up to `Kartova.slnx`), reads `src/Kartova.Api/Program.cs`, fails on any `\.Map(Get|Post|Put|Patch|Delete|Methods|HealthChecks|OpenApi|Group|Fallback)\w*\(` match. Forces future system routes into `SystemEndpoints`, where the sweep sees them.

`Kartova.Api` is already in `AssemblyRegistry.AllProduction()`; discovery is unchanged. If the health routes appear in the generated OpenAPI document, the snapshot is regenerated (name metadata only).

### TD-016 — SPA runtime config

**`web/src/shared/config/runtimeConfig.ts`** (new):
- `declare global { interface Window { __KARTOVA_CONFIG__?: RuntimeConfig } }`, `RuntimeConfig = { oidcAuthority?: string; oidcClientId?: string; apiBaseUrl?: string }`.
- `resolveConfigValue(runtime, vite, fallback)` — first non-empty string wins.
- Exposes per-key getters used by the four consumers.

**Consumers** (switch from direct `import.meta.env.VITE_*` reads): `web/src/shared/auth/AuthProvider.tsx`, `web/src/features/catalog/api/client.ts`, `web/src/admin/providers.tsx`, `web/src/admin/api/client.ts`. Each passes its own `VITE_*` value + existing default into the resolver, so dev behaviour is identical. Module-level reads stay valid because `/config.js` executes before the bundle.

**HTML** — `web/index.html` and `web/admin.html`: `<script src="/config.js"></script>` immediately before the module entry script.

**Dev stub** — `web/public/config.js`: `window.__KARTOVA_CONFIG__ = {};` — vite dev/preview serve it; resolution falls through to `VITE_*`. It is also copied into `dist`, where nginx's exact-match location shadows it.

**nginx** — `web/default.conf.template` and `web/admin.conf.template` gain:

```nginx
location = /config.js {
  default_type application/javascript;
  add_header Cache-Control "no-store" always;
  return 200 'window.__KARTOVA_CONFIG__={"oidcAuthority":"${KARTOVA_OIDC_AUTHORITY}","oidcClientId":"${KARTOVA_OIDC_CLIENT_ID}","apiBaseUrl":"${KARTOVA_API_BASE_URL}"};';
}
```

Exact match outranks the `~* \.(js|…)$` 1-year-immutable rule. CSP `script-src 'self'` already permits it; CSP stays on the HTML `location /` only.

**`web/Dockerfile`** — remove the six `VITE_*` `ARG`s and their comment; add `ENV KARTOVA_OIDC_AUTHORITY="" KARTOVA_OIDC_CLIENT_ID="" KARTOVA_API_BASE_URL=""` in the runtime stage (envsubst substitutes only defined vars — same reasoning as `CSP_EXTRA_ORIGINS`).

**Deploy**:
- Helm `values.yaml`: `web.config` and `webAdmin.config` = `{ oidcAuthority: "", oidcClientId: "", apiBaseUrl: "" }`; the TD-016 "build-time" comments removed.
- Helm `_helpers.tpl` (`kartova.spa.deployment`): three env entries from `$v.config.*` next to `CSP_EXTRA_ORIGINS`.
- `docker-compose.yml`: `web` and `web-admin` set the three vars to today's local values (`http://localhost:8180/realms/kartova` / `kartova-web` / `http://localhost:8080`; `…/realms/kartova-platform` / `kartova-admin-web` / `http://localhost:8080`).
- `deploy/README.md`, `deploy/csp-configuration.md`: build-time wording → runtime env vars; value constraint (no quotes).

### TD-017 — Re-auth loop breaker

**`web/src/shared/oidc/reauthMarker.ts`** (new) — `markReauthAttempt(now = Date.now())`, `isRecentReauthAttempt(now = Date.now())`, `clearReauthMarker()`; key `kartova.reauth-attempt` storing `{ ts }`; `REAUTH_LOOP_WINDOW_MS = 30_000`. Every storage access in try/catch. `sessionStorage` is per-origin, so tenant and admin never share the marker.

**`web/src/shared/oidc/useApiAuthBridge.ts`** — 401 handler, after the existing `redirectingRef` re-entrancy guard:
- `isRecentReauthAttempt()` → set `reauthFailed` state, `console.error`, no redirect;
- else `markReauthAttempt()` then `signinRedirect({ state: { returnTo } })` as today.

Returns `{ reauthFailed, retry }`; `retry` resets the tripped state and re-marks, then redirects (one more round-trip; a still-rejected session trips again) with the current `returnTo`.

**`web/src/shared/api/createAuthedApiClient.ts`** — `onResponse`: a non-401 response to a request that carried a Bearer token calls `clearReauthMarker()` (only an authenticated success proves the session works). Factory signature unchanged.

**`web/src/shared/oidc/ReauthFailedPanel.tsx`** (new) — `CenteredMessage`, heading "Signed in, but the session was rejected", body "The API refused the new sign-in. Try again, or sign out and sign in with a different account.", actions **Try again** (`retry`) and **Sign out** (`signoutRedirect`).

**Bridges** — `ApiAuthBridge` (`web/src/app/providers.tsx`) and `AdminApiAuthBridge` (`web/src/admin/providers.tsx`) render `<ReauthFailedPanel>` instead of `children` when `reauthFailed`.

## Error handling

| Condition | Behaviour |
|---|---|
| `/config.js` missing/404 (misrouted proxy) | `window.__KARTOVA_CONFIG__` undefined → `VITE_*` → default; browser logs the 404 |
| Env var unset in container | Dockerfile default `""` → treated as unset → fallback chain |
| `sessionStorage` throws (privacy mode) | marker helpers catch → "no marker" → today's redirect behaviour |
| 401 within 30 s of a marked re-auth | no redirect; `console.error`; `ReauthFailedPanel` |
| 401 with stale marker (> 30 s, e.g. slow password entry) | normal redirect → at most one more round-trip, then panel |
| KeyCloak unreachable (`auth.error` source `signinRedirect`) | unchanged — existing `RequireAuth` / `AdminLayout` "Sign-in unavailable" panels |
| Runtime and `VITE_*` both empty in a production build | built-in default used; one `console.warn` per key naming the `KARTOVA_*` env var (gate 7 R1) |
| 401 on a request that carried no token | never trips the breaker — plain re-auth redirect (gate 8) |

## Testing (per docs/TESTING-STRATEGY.md)

Gate-3 artifacts (deliverables):
- **Arch** (`EndpointRouteRules`): six new `ExpectedEndpoints` rows; `Every_ops_admin_route_requires_PlatformAdminOnly`; `Program_maps_no_routes_directly`. Each new rule proven discriminative once by a temporary planted violation (recorded in the ledger, not committed).
- **Integration**: no new tests — existing `HealthCheckEndpointTests` (incl. `Detailed_returns_401_for_a_tenant_realm_user`), version and OpenAPI tests stay green on the real seam (real Postgres + real JWT), proving the move preserved behaviour.
- **Vitest**:
  - `runtimeConfig` — runtime wins; empty runtime falls to `VITE_*`; both empty → default.
  - `reauthMarker` — fake timers: within/at/after window; storage-throws path.
  - `useApiAuthBridge` — 401 inside window → `reauthFailed`, no second `signinRedirect`; stale marker → redirect + re-mark; `retry` resets and re-marks, then redirects.
  - `createAuthedApiClient` — authed non-401 clears marker; anonymous non-401 and 401 do not.
  - Both bridges render `ReauthFailedPanel` when `reauthFailed` (tenant + admin); Sign out calls `signoutRedirect`.

Gate-4 artifact: **`web/scripts/check-runtime-config.sh <image> <html>`** (new) — runs the image with `KARTOVA_*` set to sentinel values, asserts `/config.js` contains them, returns `Cache-Control: no-store`, and the HTML references `/config.js`. Wired into the CI `images` job after each web image build and mirrored in `scripts/ci-local.sh images`.

E2E impact: every page load now fetches `/config.js` → full `e2e/` suite run locally before merge, noted in the ledger.

Gate 9 (live): cold-start compose with non-default `KARTOVA_*` values → `curl` both `/config.js`; sign into both SPAs in-SPA; Playwright `route` forcing persistent 401 on `organizations/me` (tenant) and `admin/session/me` (admin) → one round-trip then the panel (screenshots); `curl /health/detailed` with a tenant token → 401.
