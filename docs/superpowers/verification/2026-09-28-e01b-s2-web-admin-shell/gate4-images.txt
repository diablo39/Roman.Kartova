NOTE: the first pass of this build (Dockerfile copying build output straight into
/usr/share/nginx/html without clearing it first) left the base nginx-unprivileged image's own
stock index.html/50x.html in place alongside admin.html — COPY merges into an existing directory,
it does not replace it. For APP=web this is invisible because dist/index.html overwrites the
identically-named stock file, but for APP=admin (which only emits admin.html) the stock
index.html survived and was directly reachable at GET /index.html, where nginx's
`try_files $uri /admin.html` would find that real file and serve nginx's default welcome page
instead of falling through to the SPA. Fixed by adding `USER root` / `RUN rm -rf
/usr/share/nginx/html/*` / (COPY as root) / `USER 101` around the copy in the runtime stage of
web/Dockerfile, so the directory is cleared before the build output is copied in, and the
container still runs as the image's original unprivileged uid 101 (verified below). Rebuilt and
re-verified after the fix — listing above is from the corrected image; both `web exit=0` /
`admin exit=0` above are from the corrected Dockerfile.
