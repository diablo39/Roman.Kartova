# Control-test patterns: parameterized statements, encoding, parsing, telemetry, limits — Probe corpus

Section of `knowledge/security/control-test-patterns-dataflow.md`.


Data-flow tests drive our code with hostile-looking literal values and assert the code treats
them as plain data. Keep the probes in one shared corpus per repository — a constants file the
suites import — so every boundary is exercised with the same set:

- quote, comment, and separator characters: `O'Brien`, `a"b`, `x--y`, `1; two`
- markup and template expressions: `<b>probe</b>`, `"><i>`, `{{7*7}}`, `${7*7}`
- structure: an unknown field, a wrong-typed field, a type discriminator outside the declared set
- scale: one byte past the size cap, one level past the depth cap, one element past the count cap

Where a boundary exists, assert both directions — just-inside accepted intact, just-outside
refused with the specific error. A probe is a literal fixture, never generated by the code
under test.
