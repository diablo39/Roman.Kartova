| SEC-130 | Control test presence | Every S0/S1 security acceptance criterion in the work package, and every protective control the diff adds or alters that maps to an S0/S1 SEC entry, has at least one automated test asserting the control's protective behavior; the handoff maps each criterion to test identifiers (file plus test name); zero unmapped criteria, unless the criterion is declared not-automatable in the handoff with the manual verification recorded (the gate adjudicates); each mapped test ID appears in the recorded test-run output attached to the handoff | S1 | CWE-1059 · V15 | knowledge/security/control-verification-tests/mandate.md |
| SEC-131 | Refusal asserted | Each mapped control test asserts the deny outcome observably — wrong-role request refused with the expected status, unverifiable peer refused with a connection error, unexpected structured input rejected before reaching the sink — not only the allow path | S1 | CWE-1059 · V15 | knowledge/security/control-verification-tests/refusal-assertions.md |
| SEC-132 | Fails when control removed | For each protective-control family the diff touches, a recorded spot-check shows that disabling the control in a scratch run (inverting the guard, detaching the middleware, switching verification off) makes at least one mapped test fail; spot-check location, result, and the failing test's output line recorded in the handoff | S1 | CWE-1059 · V15 | knowledge/security/control-verification-tests/fails-when-removed.md |
| SEC-133 | Control tests durable | The diff deletes, skips, or weakens no existing control-verification test (identified by the control-test marker, or by any test named in a prior gate record's control-test map) without a gate-approved rationale recorded in the handoff; zero silent removals | S1 | CWE-1059 · V15 | knowledge/security/control-verification-tests/durability.md |
| SEC-134 | Control tests identifiable | New control-verification tests carry the project's control-test marker (naming convention, tag, or directory); the convention is established — stated where the repository documents testing, not merely proposed — no later than the first diff that ships a control test, so future diffs are checkable against SEC-133; not waivable when SEC-133 is in scope for the change | S2 | — | knowledge/security/control-verification-tests/marker-convention.md |
